# 畫面用語詞彙表

同一件事在全站只有一個名字。新增畫面、按鈕、通知、錯誤訊息、說明與圖解時，一律照這張表用字；要用新名詞，先加進這張表再寫進程式。

守衛測試會擋下「不要用」欄裡的**中文**說法（英文的靠人看，程式識別字裡本來就有 admin、error 這類字）：
- 前端 `front/src/guards/ui-terms.test.ts`：掃 `front/src` 的字串與 JSX 文字（測試檔不掃）。
- 後端 `backend/src/guards/ui-terms.test.ts`：掃 `backend/src` 的字串，也就是錯誤訊息、通知、Email 內文（測試檔不掃）。

兩支都用 `@studio/guard-kit` 讀這張表：以「、」分開、去掉全形括號裡的補充、去掉結尾的「…」、只留至少兩個中文字的詞。所以「不要用」欄要寫得機械：例外寫在「例外」欄，不要寫在「不要用」欄的括號裡。真的例外在那一行程式加註解 `guard: allow`，並說明為什麼。

規則說明寫完整句子，不用片語、括號補充、口語（例：寫「送出之後就不能再修改」，不寫「送出後不可改（鎖定）」）。

## 通用詞（範本附帶，照用）

| 這件事 | 唯一說法 | 不要用 | 例外 |
|---|---|---|---|
| 把資料存起來 | 儲存 | 保存、存檔、Save | 無 |
| 放棄這次修改並關閉 | 取消 | 放棄、Cancel | 純關閉視窗、沒有修改可放棄的叫「關閉」 |
| 看完提示後關掉 | 我知道了 | 了解、知道了、OK | 無 |
| 確認要執行某個動作 | 確認 | 確定、Yes | 問句標題（「確定要刪除嗎？」）可以用「確定」，那一行加 guard: allow |
| 新建一筆資料 | 新增… | 建立…、添加…、Create | 無 |
| 修改既有資料 | 編輯 | 更改、Edit | 句子裡講「修改」可以，按鈕不可以叫「修改」 |
| 永久移除 | 刪除 | 清除、Delete | 「移除」只用在「從清單拿掉但資料還在」 |
| 打開看內容 | 查看 | 查閱、檢視、瀏覽、View | 無 |
| 條列往下找 | 搜尋 | 查找、Search | 「查詢」只用在對外部服務（例：統編查詢） |
| 篩選條件 | 篩選 | 過濾、Filter | 無 |
| 按鈕按下去正在等後端 | 儲存中…／送出中…／載入中…／處理中… | 請稍候、Loading | 無 |
| 清單沒有資料 | 目前沒有資料 | 無資料、沒有東西、Empty | 無 |
| 系統出錯 | 發生錯誤，請再試一次 | 出錯了、系統異常、Error | 無 |
| 沒有權限 | 你沒有這個功能的使用權限 | 無權限、Forbidden | 無 |
| 尚未登入 | 請先登入 | 未登入、Unauthorized | 無 |
| 收起展開的區塊 | 收合 | 收起、折疊 | 無 |
| 回到上一頁 | 返回 | 回上一頁、回去、Back | 無 |
| 把資料匯成檔案 | 匯出 | 導出 | 「下載」只用在既有的檔案 |
| 把檔案讀進來 | 匯入 | 導入 | 「上傳」只用在檔案本身 |
| 方案名稱 | 大寫英文或中文全名（例：PRO、MAX） | Pro、pro | 無 |
| 系統裡的使用者 | 成員 | 用戶 | 說明文字講「使用者」可以 |
| 有管理權限的成員 | 管理員 | 管理者、Admin | 無 |
