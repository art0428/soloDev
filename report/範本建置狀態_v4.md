## 二、第四批做了什麼

名詞先講清楚：

- **skill**：給 Claude Code 的一份做事說明書，說到觸發詞時自動照著做。`.skill` 檔就是一個 zip，裝進 Claude 後生效。
- **scaffold**（腳手架）：先把專案該有的資料夾一次建好，之後只往裡面放東西。
- **Cloud Build**：Google Cloud 的雲端建置服務，把程式打包成容器映像。**Artifact Registry** 是存放映像的倉庫。
- **.gcloudignore**：決定 `gcloud builds submit` 要上傳哪些檔，作用跟 `.gitignore` 一樣。
- **煙霧測試**：部署完立刻打幾個免登入、唯讀的網址，確認服務活著、守衛沒掉。
- **拋棄式庫**：測試時臨時建、跑完就刪的資料庫，名字隨機，不會碰到開發庫。

### 2.2 studio-init 怎麼跑

在空資料夾對 Claude Code 說「初始化專案」：

1. 檢查目前位置：只接受空資料夾，或只有 `.git`、`README.md`、`docs/prototype/` 的資料夾；其他情況停下來問。
2. 複製範本快照（不覆蓋既有檔），子 skill 的 `.tpl` 改回 `SKILL.md`，腳本設執行權限。
3. `bash scripts/scaffold.sh` 建齊資料夾。
4. `git init`、檢查沒有 `.env` 被加進去、首次提交，提交後才啟用 pre-commit。
5. 驗證：25 個關鍵檔都在、沒有殘留 `.tpl`、工作目錄乾淨、pre-commit 已啟用。
6. 印出結構樹與接下來四件事（放原型 → `init.sh` → MCC 憑證自己填 → 步 1 Prompt），最後問你要避開的真實名字，寫進禁字清單。

skill 不代裝相依、不代建開發庫、不碰任何密鑰；這些由 `init.sh` 印出指令讓你自己跑。

## 三、與既有專案隔離（11/1 的指示）

你 11/1 的指示：這份資料要跟既有專案的所有東西隔離，不用到它的資料或程式，之後整個資料夾會搬走。做法與結果：

- **程式**：逐檔比對，凡是從既有專案照抄或改寫來的程式都重寫，包括 `migration-check.ts`、`dates.ts`（測試重寫成 14 題，含夏令時間那天只有 23 小時）、`datetime.ts`、`oidc.ts`、`mcc-member.ts`、`Spinner.tsx`、`BusyButton.tsx`、`disposable-db.sh`、`verify-env.sh`、`run-e2e.sh`、`run-tests.sh`。重寫後再比一次，相同的行只剩框架樣板（Prisma 自動產生的 SQL、`export default defineConfig({`、`userEvent.setup()`、package.json 的 script 慣例），沒有實質邏輯。
- **示範世界**整個換掉：禾木文具有限公司（管理員許經理、業務蔡業務），客戶星河文理補習班、青田咖啡館，商品是紙、筆、資料夾、白板筆。
- **文件**：dev-guidelines 的經驗紀錄改成「前一個專案」的通用說法，拿掉特定數字與畫面細節；手冊出 v1.1（`report/管理者工作室AI單人開發手冊_v2.md`）；配套清單出 v2（`report/手冊配套文件與初始化程式清單_v2.md`），表中「從某專案搬」改成實際做法。兩份 v1 照不覆蓋規則保留。
- **路徑**：`solo_dev/` 內沒有任何絕對路徑，也沒有指向既有專案目錄的引用；打包腳本用相對路徑。
- **檢查結果**：範本程式、skill、v2 文件裡都沒有既有專案的名稱。還有名稱的只剩 `report/` 裡兩份舊版（手冊 v1、配套清單 v1），是歷史紀錄，搬走前要不要刪由你決定（見第七章）。

## 五、驗證時抓到並修掉的問題

### 5.1 pre-commit 放行真的 .env（真 bug，已修）

原本的寫法是「暫存的檔裡有 `.env.example` 就整個放行」，所以 `.env` 跟 `.env.example` 同一次提交時，真的 `.env` 會被提交上去。改成逐檔判斷，加 6 題測試；換回舊 hook 確認新測試會紅。

### 5.2 後端單檔測試其實跑整套（已修）

文件教 `pnpm --filter backend run test src/routes/x.test.ts`，但腳本只看 `TEST_FILES` 環境變數，接在後面的檔名被忽略，結果整套都跑了，看起來還是綠的。腳本改成兩種都吃，文件三處跟著改。

### 5.3 測試庫名看不出是哪個專案（已修）

庫名代號取的是 `backend/package.json` 的名字，每個專案都叫 `backend_…`。改取根目錄的專案名（去掉 `@scope/`、只留英數、最多 24 字、全是中文就用 `app`），加 5 題測試；換回舊寫法確認其中 3 題紅。

### 5.4 其他小修

- 沒有 pnpm 時，根目錄的 `pnpm dev`、`pnpm test` 內部又呼叫 pnpm 會失敗：`init.sh` 最後提示先執行 `corepack enable`。
- `pnpm install` 的輸出夾帶更新提示框：`init.sh` 成功時只印一行摘要，失敗才印最後 30 行。
- 煙霧測試有一項標籤寫 GET、實際送 POST：改正標籤。

## 七、要你決定或自己做的

1. **project-init 與 studio-init 觸發詞衝突**：兩個都吃「初始化專案」。建議安裝 `skill/studio-init_v1.skill` 之後移除 project-init（v6）。
2. **搬走前清掉測試產物**：範本資料夾目前 605 MB，幾乎都是 node_modules。打包 skill 時已排除，但整個資料夾搬走前建議刪掉 node_modules、`.claude/tmp`、E2E 產物（指令附在對話回覆裡；這類刪除由你自己跑）。
3. **兩份含舊名稱的 v1 文件**（手冊 v1、配套清單 v1）：要留作歷史，或搬走前刪掉。
