# 手冊配套文件與初始化程式清單 v2

※ v2 只改「來源」的寫法：範本的程式與文件全部重寫，不讀、不抄任何既有專案的程式或資料，表中原本寫「從某專案搬」的地方改成實際做法。規劃內容、章節編號（含 3.2 第 5 點的驗收清單）與 v1 相同。

手冊本身只是一份 markdown。學生要能「放進 Claude Code 就照做」，還需要一組配套檔案讓 Claude Code 自動讀到規則、自動跑檢查，以及一支初始化程式把這些檔案一次建出來。這份清單分三部分：

- 第一章：配套檔案總表（每個檔案的用途、誰負責填、現有 project-init v6 有沒有）。
- 第二章：關鍵檔案的內容大綱（CLAUDE.md、dev-guidelines、pre-commit、check.yml、部署說明現況表等）。
- 第三章：初始化程式 studio-init 的規格（做什麼、不做什麼、建出來的樹）。

判定符號：◎ v6 已有可直接沿用、△ v6 有但要改、✕ v6 沒有要新建。

## 二、關鍵檔案內容大綱

### 2.1 CLAUDE.md（範本）

分八段，每段只放短規則，做法細節指向 skill：

1. **專案資訊四行**（學生填）：專案名、一句話說明、業務時區、正式網址。
2. **開工先讀**：docs/PROGRESS.md、docs/DEVLOG.md 最新 3 筆、.claude/skills/dev-guidelines/SKILL.md；動到登入先讀 mcc-integration。
3. **文件優先序**：CLAUDE.md 與使用者當下指示 ＞ dev-guidelines ＞ 手冊。
4. **資料庫鐵則**：開發庫不准清除、還原、重建；測試一律走 run-tests.sh 的拋棄式庫；瀏覽器驗收一律 verify-env.sh；只新增的 migration 可套開發庫、會刪東西的一律先問。
5. **契約與測試**：先改 openapi.yaml 再改程式、改完 openapi:gen；每個新行為都要有測試、失敗路徑優先；守衛測試要驗它會紅；破壞性變更三件事；測試三層（改動中相關檔、併回前動到那端整套、全套＋E2E 留夜間）；每個畫面一條掛載測試；按鈕處理中四件事；兩種時間的三個不可。
6. **提交與合併**：分支 claude/<切片名>；全綠才 merge --no-ff 回 main；commit 中文、引用 D 編號；push 與部署等使用者指示；合併後更新 PROGRESS.md（標驗收等級）與 DEVLOG.md；修到正式機也有的 bug 必標熱修。
7. **正式機**：只有部署對話碰；任何狀態變更當次要使用者允許；部署前臨場查 pending migration、備份；破壞性 migration 先部署程式再跑；部署後打 tag、更新現況表、斷線。
8. **停下來問 vs 自行決定**：業務規則兩種解讀、破壞性變更、刪除性操作、安全取捨、要加付費服務 → 問，固定格式「背景一句話＋2〜3 選項＋建議＋影響範圍」；純技術選型自行決定記 DEVLOG。
9. **防造假**：紅燈只准改實作或回報需求疑義，不准弱化斷言、skip、刪測試；tests/ 的刪改要在報告標紅。
10. **指令規範**：不把輸出重導向到檔案、接管線看摘要；一次 Bash 一件事；用 pnpm --filter 不用 cd &&；寫檔用 Edit／Write。

### 2.2 .claude/skills/dev-guidelines/SKILL.md（範本）

範本自寫，章節如下：

0. 本檔怎麼維護（「放入 skill」＝第 7 節加一條並回寫做法）
1. 開工前（開發庫不碰、拋棄式環境、看分支、看測試基準）
2. 契約優先（openapi 先改、lint 基準、OAS 3.0 nullable 寫法、漂移檢查）
3. 資料庫與 migration（只新增、nullable、索引命名、回填腳本慣例、Prisma.DbNull）
4. 測試（三層、E2E 一檔一帳號與冪等、user-event、覆蓋率報告用途、守衛測試要驗它會紅、破壞性變更三件事）
4.5 處理中四件事與兩個例外、骨架屏何時用
4.6 時間與時區（兩種時間、只有一套實作、九條鐵則、測試怎麼寫、機械式 grep 清單）
5. 提交、合併、部署
6. 回報格式（先結果、再驗證方式與環境狀態；測試數字用表格、說明是哪個環境的綠）
7. 經驗紀錄（範本先放前一個專案最有代表性的五條，寫成通用說法：時間慢八小時、migration 沒套 500、樣板一改舊資料案例消失、按儲存沒反應、E2E 相互汙染，當作教材）

### 2.3 .claude/skills/nightly-guard/SKILL.md（範本）

範本自寫的通用版：

- 鐵則：只在隔離副本做；產品 bug 只回報不修；不 push 不部署不碰正式機；任何一題紅就停、什麼都不併回、狀態不前進。
- 程序：看現況 → 匯出 main 到隔離副本 → 後端全套 → admin 全套（有的話）→ 前端全套＋lint → 等埠口空 → 整套 E2E → 全綠更新 test-baseline.md → 狀態檔前進。
- 紅了怎麼辦：單獨重跑分辨每次紅／偶發、用 git log 找可能的提交、寫報告。
- 報告格式：第一行結論五選一、看了哪些提交、全套關卡表格（與上次比題數有沒有變少）、產品問題清單、待決定、環境狀態。
- 說明與影片同步那一段放在「選配」小節，有做使用說明功能的專案才啟用。

## 三、初始化程式 studio-init 規格

做法沿用現有 project-init skill（複製模板快照 → 建目錄 → git init → 驗證 → 收尾），模板換成手冊 v1.0 的那一套。

### 3.1 觸發

學生在空資料夾開 Claude Code 說「初始化專案」「開新專案」「照手冊建專案」。

### 3.2 做什麼

1. 確認目標資料夾是空的（只有 .git／README.md 可以），否則停下來問。
2. 複製 assets/template/ 到目標資料夾（cp -Rn，不覆蓋既有檔），把 .tpl 改回原名。
3. bash scripts/scaffold.sh 建齊目錄。
4. git init -b main、設 core.hooksPath scripts/git-hooks、首次 commit「chore: init from studio-template v1」。
5. 驗證關鍵檔案存在：CLAUDE.md、docs/管理者工作室AI單人開發手冊.md、.claude/skills/dev-guidelines/SKILL.md、.claude/skills/nightly-guard/SKILL.md、.claude/agents/qa-reviewer.md、api/openapi.yaml、scripts/init.sh、scripts/verify-env.sh、scripts/git-hooks/pre-commit、.github/workflows/check.yml、deploy/部署說明.md、docs/decisions.md、docs/PROGRESS.md、docs/ui-terms.md。
6. 固定收尾輸出：頂層結構樹；提醒接下來三件事：(a) 把 index_v1.html 放進 docs/prototype/；(b) 到 MCC 建 Group／Service，測試 Group 憑證自己填 .env，不要貼進對話；(c) 執行 bash scripts/init.sh <專案名>，然後貼步 1 的 Prompt。另印出建立 nightly-guard 排程的指令。

### 3.3 不做什麼

- 不覆蓋、不刪除既有檔案。
- 不自動開始步 1、不產生業務程式、不填需求。
- 不索取、不代填、不顯示任何 secret 值。

### 3.4 scripts/init.sh 做什麼

```
bash scripts/init.sh <專案名> [--with-admin]
```

1. 把 <專案名> 寫進 CLAUDE.md 專案資訊第一行、package.json name、README 標題。
2. 檢查 docs/prototype/index_v1.html 存在，不在就停並提示。

## 四、建議的建置順序

把這份清單做出來大約分四批，每批都能單獨驗：

| 批 | 內容 | 驗收方式 |
|---|---|---|
| 一 | 文件類：CLAUDE.md、dev-guidelines、nightly-guard、qa-reviewer、decisions／PROGRESS／ui-terms／test-baseline 範本、部署說明範本、release-checklist | 用一個假專案開 Claude Code，貼步 1 Prompt，看它有沒有照規則讀檔與回報 |
| 二 | 程式骨架：openapi 骨架、api-client 產生、front／backend 能跑的登入骨架、示範世界、run-tests.sh、verify-env.sh | pnpm dev 能跑、mock 模式登入成功、pnpm test 全綠 |
| 三 | 守衛與檢查：守衛測試、pre-commit、check-contract-drift、check.yml、vitest 設定 | 故意塞違規 commit 看 pre-commit 擋下；推到 GitHub 看 check.yml 綠 |
| 四 | studio-init skill：模板快照打包、SKILL.md、init.sh、scaffold.sh | 在空資料夾說「初始化專案」，跑完照 3.2 第 5 點驗證檔案齊全 |

這四批做完，學生拿到的就是：一本手冊、一個說「初始化專案」就建好的範本、一組會自動擋錯的檢查。
